# v0.4.0 — State Infrastructure (P0-1) Implementation Report

## Summary

Implemented the persistent state infrastructure for loshu-sdlc, complementing
the v0.3.0 DAG state machine with project-level memory in two files:

- `.loshu-sdlc/state/cycle.json` — cycle counter, per-stage state, timestamps, sha fingerprints, origins
- `.loshu-sdlc/state/gates.jsonl` — append-only JSONL event log of every gate run

Exposed via a new `loshu-sdlc cycle` CLI subcommand. Every stage hook now
persists stage transitions and appends gate events; `plan-exit` auto-creates
a cycle on first run; `maintain-exit` forks an incident cycle on 3σ incidents.

## Concerns

### Concurrency

The mkdir-lock pattern (`mkdir path.lock` + EEXIST retry) provides serialization
on POSIX. On Windows NTFS, `mkdir` is also exclusive (returns EEXIST on race),
so the same pattern works. The lock has a 5-second timeout — long enough for
typical hook runs but short enough that a crashed process won't block forever.

Concurrent `incrementCycle` calls are serialized through the same lock. The
test suite includes a 10-way concurrent increment test that verifies all
10 increments produce unique ids (1..10) — this passed 5/5 runs.

`appendEvent` for `gates.jsonl` reads the existing content, appends the new
line, and writes back atomically. This is **O(n) per append** where n is the
log size. For very long-running projects this could become slow; consider
switching to `fs.appendFile` with `O_APPEND` mode in a future revision if the
log grows past ~10k lines. (Not a problem for typical SDLC timescales.)

### Atomic-write semantics on Windows

`fs.rename` on Windows replaces the destination atomically *only* on the same
volume. Since `cycle.json` and `cycle.json.tmp` always live in the same
directory (`.loshu-sdlc/state/`), this is guaranteed. The library comments
document this assumption.

### Hook integration bash idiom

The hooks parse `cycle.json` with a fragile `grep -oE` regex to extract
`current_cycle`. This is a deliberate trade-off: avoiding a Node.js bootstrap
per hook invocation keeps latency low (sub-100ms per hook). If the JSON
format ever changes, the grep must be updated in lockstep.

### Eval suite results.json modified

`tests/evals/results.json` was regenerated by the eval run and is included
in the release commit. This is expected — the file is the recorded output of
the latest eval run.

### Did NOT update `test-exit.sh`

The spec listed only `plan-exit`, `design-exit`, `build-exit`, `deploy-exit`,
`maintain-exit`. `test-exit.sh` was not updated to log to `gates.jsonl`. The
test stage already shows up in cycle.json (its `state` field can be set via
`cycle set test <state>`) but no automatic gate-event emission. This can be
added in a follow-up if needed.

### TypeScript strict mode flag

The library uses `noUncheckedIndexedAccess` (inherited from
`tsconfig.base.json`). All array/object accesses use `?? null` defaults to
satisfy the strict check. Some test assertions read the cycle.json file
directly rather than parsing the captured console output — this is more robust
and avoids chalk ANSI escaping edge cases.
