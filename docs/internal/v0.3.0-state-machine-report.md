# v0.3.0 DAG State Machine Report

**Date:** 2026-09-14
**Goal:** Replace the implicit file-existence-based stage inference
with a formal DAG state machine where every artifact carries an
explicit `state` field and every transition follows a defined edge set.

---

## Summary

Every SDLC artifact now has a top-level `state:` field in YAML
frontmatter. Hooks read and update that field; a new CLI command
(`loshu-sdlc state`) lets humans and CI inspect and transition state.
A formal DAG definition lives at
`packages/plugin/state-machines/artifact.json`. The cross-stage rule
(stage S may not become `accepted` unless stage S-1 is `accepted`)
is enforced in the hook chain and the `--validate` subcommand.

## Concerns

1. **Stash + release interaction.** `scripts/release.mjs` checks for a
   clean working tree, but `pnpm test:eval` regenerates
   `tests/evals/results.json`. The script does `git add -A` before
   committing, so the regenerated file ends up in the release commit
   (visible in `f834735`). For local-only development this is fine,
   but in CI the evaluator should `git stash push tests/evals` before
   running `release.mjs`, then `git stash drop` afterwards.

2. **Cycle restart path is implicit.** The cross-stage rule exempts
   the first stage (`plan`) so a new cycle can begin without the old
   cycle's `intent.md` being `accepted`. There is no explicit
   `cycle.json` migration; we rely on `/sdlc-init` (out of scope for
   this task) to bump `current_cycle`. If `cycle.json` is missing we
   default to cycle 1 and title `inferred`.

3. **`state` and `status` coexistence.** All six schemas still expose
   the legacy `status` enum (`draft | accepted | rejected`). The new
   `state` field is broader (`... | iterating | blocked | archived`).
   Hooks read `state` first, fall back to `status`. The `state`
   command writes both fields on transitions into `draft` / `accepted`
   for backward compatibility with downstream consumers. A future
   major release can drop `status`.

4. **No `--transition` automation for `archived`.** The DAG allows
   `accepted → archived` (e.g. a new cycle supersedes this artifact),
   but the hooks never auto-archive; an `archived` file must be set
   manually via `loshu-sdlc state <stage> <file> --transition archived`.
   A future iteration could add `/sdlc-cycle` to automate this.

5. **Bash hook integration test coverage.** One of the two
   hook-integration tests invokes `bash plan-exit.sh`. It depends on
   `npx --no-install loshu-sdlc` being on PATH and the bundled plugin
   symlinks being present; in CI sandboxes without `npx` this test is
   silently skipped (warns instead of failing). Acceptable for now
   but worth wiring into CI explicitly.

6. **`/sdlc-status` markdown can't be auto-tested.** It's a prompt
   for Claude, not a script. The change is verified by reading the
   new prompt body, not by an automated check.
