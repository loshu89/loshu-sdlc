# v0.8.0 Design — CLAUDE.md + Spec Backlog Cleanup

> **Status:** Draft (awaiting user review)
> **Date:** 2026-09-18
> **Target version:** v0.8.0

## Goal

Close two gaps identified in `docs/internal/playbook-coverage-analysis.md` (commit `28ea70e`):
1. **`CLAUDE.md`** — institutional knowledge file the AI-Native SDLC playbook calls out explicitly; the project has none.
2. **Spec backlog cleanup** — explicit one-line dispositions for every deferred item in `docs/superpowers/specs/doc-mgmt/6-scope-acceptance.md` §6.1.2 so future v0.9.x / v1.0 brainstorming doesn't relitigate the same questions.

## Non-Goals

- ❌ Maintain → Plan loop closure (per `playbook-coverage-analysis.md`) — separate spec, deferred to v0.8.x+.
- ❌ Web UI dashboard — spec §6.1.2 v1.0 scope.
- ❌ New CLI commands or runtime behavior changes — v0.8.0 is documentation-only at its core.
- ❌ Auto-revert on failed merge, branch protection enforcement, webhook receiver — dispositioned in §3 of this spec, but not implemented.

## Architecture

Two deliverables, both text:

1. **`/CLAUDE.md`** — a single Markdown file at the project root capturing conventions any agent (or human) needs to navigate the repo. Sections mirror what an agent actually does in this repo: install, build, test, lint, release, debug SDLC failures, work with the skill/plugin system.

2. **`docs/superpowers/specs/2026-09-18-v0.8.0-backlog.md`** (new file) — a one-page spec addendum that disposition each §6.1.2 deferred item as: **deferred indefinitely with rationale** / **deferred to v0.8.x with concrete requirement** / **deferred to v1.0**.

No new source code, no new tests, no new dependencies.

## Data Flow

None. v0.8.0 is text-only — no runtime changes, no new files read at runtime, no new env vars.

## Error Handling

None. If the CLAUDE.md is wrong or stale, future agents will discover it via test/typecheck failures and fix it. Same for the backlog addendum.

## Testing Strategy

- **CLAUDE.md**: Manual review only. The file's content is reviewed against the actual repo state during writing; agents using the file in subsequent sessions provide implicit regression coverage (if a command documented in CLAUDE.md doesn't work, an agent reports it).
- **Backlog addendum**: Manual review only. Cross-check against §6.1.2 source.
- **Verification gauntlet**: `npx pnpm@9.0.0 typecheck && npx pnpm@9.0.0 lint && npx pnpm@9.0.0 test` — must remain green. Neither file touches source, so all 229 tests still pass.

## Risk Assessment

**Low risk** for both deliverables:
- CLAUDE.md is documentation; no runtime impact.
- Backlog addendum is a spec annotation; no runtime impact.
- Neither change touches code, tests, or dependencies.
- Worst case: CLAUDE.md is wrong/stale → agents waste time, then update it.

The only real risk is **CLAUDE.md being misleading** — i.e., documenting a convention that the repo doesn't actually follow. Mitigations:
- Draft from actual repo state (read existing files, run the commands, document what's true).
- Have the spec self-review explicitly verify every documented command actually works.
- Future agents reading CLAUDE.md will surface inconsistencies quickly.
