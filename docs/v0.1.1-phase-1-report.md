## Item 3 — Hooks path mismatch fix

**File modified:** `D:/workspace/3.my/SDLC/packages/cli/src/commands/create.ts`

**Change:** After `bundlePlugin(pluginSrc, targetPath)`, the scaffolder now
creates a symlink:

- Canonical path: `<target>/.claude/hooks`
- Target: `<target>/.claude/plugins/loshu-sdlc/hooks`
- `hooks.json` references `bash .claude/hooks/<script>.sh` — these now resolve.

**Implementation details:**
- Imported `ensureSymlink` from `fs-extra` and `process` from `node:process`.
- Symlink type is `'junction'` on Windows (no admin required) and `'dir'` on
  POSIX. This avoids the `EPERM` that real symlinks raise on Windows.
- Wrapped in try/catch; on failure logs a yellow warning but does not throw,
  so scaffolder continues. Idempotent on subsequent runs.

**Why `hooks.json` itself is NOT changed:** The spec says hooks.json paths must
stay canonical (marketplace users have hooks directly under `.claude/hooks/`,
so the reference is already correct for that case). The symlink is the bridge
that makes bundled installs behave the same.

**Verification (local tests):**


- After fix: `npx pnpm@9.0.0 test` shows 22/22 passing with no EPERM warning.

## Concerns

1. **CI not executed locally.** No GitHub Actions runner is available in this
   sandbox. The workflow is structurally correct (matches spec verbatim) and
   scripts mirror the local `package.json`, but it has not been observed
   passing on a real runner. First push to `main` will trigger it; watch for
   any pnpm-store / cache issues if they arise.

2. **Symlink gitignore coverage.** Task statement says "Symlink should NOT be
   committed — already covered by the existing `.gitignore`." For
   scaffolded user projects this is fine — the user's `.gitignore` is theirs.
   However, the SDLC repo's own root `.gitignore` does not list `.claude/`.
   This is fine for the SDLC repo (we never create `.claude/hooks` in the
   monorepo itself), but if `.claude/` is ever added to the repo it should
   be gitignored.

3. **Symlink on Windows + Vitest temp dir.** Vitest tests create the
   symlink inside `C:\Users\...\Temp\loshu-...`. The junction point worked
   end-to-end during testing. Real users running the scaffolder will get the
   same junction behavior on Windows.
