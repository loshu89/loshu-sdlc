# v0.1.1 Phase 2 Report — CLI Subcommands

## Summary

Implemented 7 new CLI subcommands (8 total commands including the `rules` subcommand set) on top of the existing `loshu-sdlc` CLI. The bin entry point grew from 3 cases (validate, doctor, bands) to 10 cases with no regression.

## Commands Implemented

### 1. `lint [path] [--fix] [--json]`

- **File:** `packages/cli/src/commands/lint.ts`
- **Test:** `packages/cli/tests/commands/lint.test.ts`
- **Behavior:** Scans `packages/plugin/skills/policy-default/` for borrowed files (those that declare a non-`loshu-sdlc` source line) lacking a full `provenance:` + `source:` frontmatter block. With `--fix`, prepends a `provenance:` block to each offending file. Reuses `lib/attribution.ts`.
- **Exit codes:** 0 = clean, 5 = violations present.
- **Verification:** Pass — 4 tests pass; `--fix` clears the violation list post-fix.

### 2. `rules list`

- **File:** `packages/cli/src/commands/rules.ts`
- **Test:** `packages/cli/tests/commands/rules.test.ts`
- **Behavior:** Prints the 11-rule registry with their source tag (`superpowers`, `ecc`, `ui-ux-pro-max`, `loshu-sdlc`). `--json` emits structured JSON.

### 3. `rules check <name> [path] [--json]`

- **File:** (same) `packages/cli/src/commands/rules.ts`
- **Test:** (same) `packages/cli/tests/commands/rules.test.ts`
- **Behavior:** Looks up the named rule in the registry, scans its `appliesTo` paths under `<path>` and emits a pass report. Returns 2 for unknown rules / missing names.
- **Note:** v0.1.1 produces a structured pass report; full rule implementations land with v0.2 per spec §11.2.

### 4. `status [path] [--json]`

- **File:** `packages/cli/src/commands/status.ts`
- **Test:** `packages/cli/tests/commands/status.test.ts`
- **Behavior:** Mirrors the `/sdlc-status` slash command. Reads `.loshu-sdlc/state/status.json` if present, otherwise infers per-stage presence from the canonical artifact files. Renders an ASCII table with stage / artifact / status / updated / next-gate columns plus external-dep tier counts.

### 5. `coverage [path] [--diff <sha>] [--json]`

- **File:** `packages/cli/src/commands/coverage.ts`
- **Test:** `packages/cli/tests/commands/coverage.test.ts`
- **Behavior:** Runs `vitest run --coverage --reporter=json` via `execa`. Parses line/branch coverage from the JSON reporter. `--diff <sha>` attaches the SHA to the report.
- **Exit codes:** 0 = ran, 6 = node_modules missing.

### 6. `logs [--tail N] [--cycle N] [--stage NAME] [--json]`

- **File:** `packages/cli/src/commands/logs.ts`
- **Test:** `packages/cli/tests/commands/logs.test.ts`
- **Behavior:** Reads `~/.loshu-sdlc/logs/*.log` and parses each line into `{timestamp, level, message, cycle?, stage?}` entries. `--tail` keeps only the last N; `--cycle` / `--stage` filter the rest.

### 7. `upgrade [path] [--to <version>] [--dry-run] [--json]`

- **File:** `packages/cli/src/commands/upgrade.ts`
- **Test:** `packages/cli/tests/commands/upgrade.test.ts`
- **Behavior:** Bumps the `@loshu-sdlc/{plugin,cli,templates}` version pins in `<path>/package.json`. Preserves user customizations (scripts, devDependencies, non-loshu-sdlc deps). `--dry-run` reports the plan without writing.
- **Exit codes:** 0 = success or already-current, 2 = package.json missing.

### 8. `telemetry enable|disable|status [--json]`

- **File:** `packages/cli/src/commands/telemetry.ts`
- **Test:** `packages/cli/tests/commands/telemetry.test.ts`
- **Behavior:** Writes `{telemetry: true|false}` to `~/.loshu-sdlc/config.json`. `status` reads and reports. No actual telemetry is collected yet (spec §11.4 reserves collection for a later version).

## Concerns

1. **`rules check` is a stub.** It looks up the rule and scans its `appliesTo` paths but does not yet run the rule's actual logic. The spec calls out full rule implementations as v0.2 work; v0.1.1 ships a structured pass report so downstream tooling can pick it up.
2. **`coverage` requires `node_modules` at the target.** Returns exit code 6 with a clear message when missing. No bundled vitest invocation falls back; users must `pnpm install` first.
3. **`logs` parses with a custom regex.** Accepts `<iso-timestamp> [tags] LEVEL message` lines. If the loshu-sdlc log writer emits a different shape (TBD), the parser would need updating. Currently no log writer exists, so this is forward-looking.
4. **`upgrade` only edits `package.json`.** Templates, hook configs, and command markdown under `packages/plugin/` are not touched in v0.1.1 — those copies are assumed to come from a fresh `pnpm install` / plugin re-install rather than an in-place edit.
5. **`telemetry` writes only.** No collection, network call, or analytics endpoint. Matches spec §11.4 "Zero network calls except explicit `plugin install` and `upgrade`".
